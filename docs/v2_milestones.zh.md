# FramePilot v2 里程碑

> 语言：[English](v2_milestones.md) | **中文**

本文把 v2 计划落实为可执行的开发检查点。每个里程碑应以小而可审阅的提交实现，并在同一切片中更新测试和文档。

## v2.0 基础

目标：保持仓库可维护，并准备好结构化的 v2 开发。

必需结果：

- 根脚本的 setup、dev、lint、typecheck、test、E2E 和 verify 有文档
- v2 产品、架构、测试、算法和迁移文档存在，或从 README 链接
- 本地优先和原片安全规则被保留
- 现有 v1 工作流仍能运行

验证：

```bash
npm run verify
```

当包含浏览器工作流变更时，运行 `npm run test:e2e`。

## v2.1 处理与进度

目标：让处理基于任务、可见、可重试。

必需结果：

- 处理创建任务记录并快速返回
- 前端轮询任务状态
- 进度暴露当前步骤、总项、已处理项、失败项和百分比
- 失败项被记录且不让整个任务崩溃
- 过期或中断的任务可以重试
- 重跑未变更项目时避免不必要的重新分组

验证：

- 后端处理集成测试
- 处理进度前端测试
- `npm run verify`

## v2.2 筛选工作区

目标：让复核对真实筛选会话高效。

必需结果：

- 照片和组的键盘优先导航
- Pick、Maybe、Reject、Unreviewed 和 0-5 星级更新
- 缩放和对比模式
- 每个项目持久化的复核进度
- 在安全的情况下做乐观状态和星级更新
- 大胶片条、组和对比列表的有界渲染
- 有用的加载、空状态和错误状态

验证：

- 导航和进度辅助函数的前端单元测试
- mocked E2E 筛选工作流
- 当工作流变更影响浏览器/API 流程时的真实本地 smoke E2E
- `npm run verify`

## v2.3 导出与互操作

目标：让本地导出对下游编辑工作流可靠。

必需结果：

- CSV、ZIP 和文件夹导出写入本地产物
- 空导出请求在写入产物前被拒绝
- 失败导出被记录，并在可能时删除部分产物
- 已完成的 CSV 和 ZIP 产物可下载
- 文件夹导出清楚显示本地输出路径
- 导出历史显示模式、状态、所选状态、所选数量和输出路径
- XMP sidecar 导出在实现前保持计划中且文件安全

验证：

- 导出内容、文件存在、状态过滤、下载和文件安全的单元/API 测试
- 前端导出选择测试
- 包含 UI 变更时的 E2E 导出工作流
- `npm run verify`

## v2.4 算法质量

目标：改进确定性分组、排序、置信度和解释。

必需结果：

- 导入照片存储感知哈希
- 分组使用候选窗口、元数据兼容、哈希距离、embedding 回退和 union-find
- 分组后拆分过大的拍摄时间跨度
- 排序使用确定性基线和上下文权重
- 组置信度摘要被持久化
- 解释点出实际排序原因，并将人脸/眼睛信号标为实验性

验证：

- 连拍、元数据不匹配、文件名回退、哈希距离和时间跨度拆分的分组测试
- 锐度、曝光、噪声、上下文权重和解释文本的排序测试
- `npm run verify`

## v2.5 性能与可靠性

目标：验证大型本地工作流，同时不让默认测试套件变慢。

必需结果：

- 存在合成数据集生成器
- 100 张照片工作流由自动化测试覆盖
- 500 和 2,000 张照片工作流有文档或通过可选 smoke 命令验证
- 后端索引支持常见大项目查询
- 前端避免一次渲染数千张图像
- 中断或重复处理可恢复

验证：

```bash
npm run perf:api -- --output /tmp/framepilot-perf-targets --counts 100 500 2000
```

smoke 应报告耗时、失败项数量、组数、导出和峰值内存。

## v2.6 可选高级支持

历史 Goal Mode 标签。**第八阶段 HEIC 静帧预览**（`docs/plans/2026-09-04-heic-preview.zh.md`）已交付；它不是整个 v2.6 捆包。交付上的第七阶段是处理作业取消，已经交付。交付第九阶段是剩余 stretch S9.00–S9.13（`docs/plans/2026-09-04-remaining-stretch.zh.md`）。不要发明第十阶段。

第八阶段（已交付）：

- 仅 HEIC/HEIF 静帧预览

仍属更后：

- RAW 内嵌预览提取
- 可选本地模型注册表
- 可选本地人脸、眼睛、embedding 或美感模型
- 模型来源、许可证、体积和性能文档

发布规则：

- 不提交大模型文件
- 无云处理要求
- 不支持的格式必须继续优雅失败
- JPEG、PNG 和 WebP 基线工作流必须保持稳定
