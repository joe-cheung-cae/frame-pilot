# FramePilot v2 真实世界算法验证

> 语言：[English](v2_real_world_validation.md) | **中文**

## 1. 目的

本文定义 FramePilot v2.0 的发布阻断级手工算法置信度门槛。自动化测试和生成图像基准可以验证确定性行为、本地工作流安全和性能 smoke 覆盖，但它们不能证明分组、排序、解释和导出在真实摄影师风格的照片集上表现良好。

在打无限定条件的 v2.0 发布候选标签之前，使用本协议。产品负责人应验证非私人本地照片集，用 `docs/templates/algorithm_validation_notes_template.zh.md` 记录观察，并决定发布是否可以继续、是否需要更多验证，或是否需要聚焦的后续工作。

本任务仅用于收集验证证据。收集笔记时，不要更改评分、分组、排序、解释规则、阈值、支持格式或产品范围。

## 2. 隐私规则

- 不要提交私人照片。
- 不要提交生成的项目目录。
- 除非导出不含敏感文件名且发布负责人明确要求跟踪，否则不要提交导出。
- 不要提交生成的缩略图、预览、缓存、SQLite 数据库、ZIP 文件、浏览器 trace 或本地基准输出。
- 只使用非私人或可丢弃的照片集，例如公有领域照片、专门拍摄的测试照片，或不含敏感人物、地点、文件名或元数据的照片。
- 验证笔记可以引用脱敏文件名、短 ID、本地 UI 照片 ID，或复核者自建的别名。
- 如果数据集权利不清、含私人主体、敏感地点或敏感文件名，不要把它当作发布证据。
- 验证过程中永远不要修改、删除、覆盖或移动原始源照片文件。

## 3. 推荐数据集层级

Tier A：30-50 张照片，快速健全性验证。

- 用于自动化门槛变绿后的第一次手工通过。
- 至少包含一组连拍或近重复，以及至少一张技术上偏弱的图像。
- 预期结果：在更大复核之前，抓住明显的错误合并、漏组、误导性解释或导出问题。

Tier B：100-300 张照片，发布候选验证。

- 作为主要的 v2.0 手工发布门槛。
- 包含场景类型、光照、方向、元数据质量和相似帧的真实混合。
- 预期结果：提供足够证据，以决定是否可以打 v2.0 标签、是否需要更多验证，或是否需要带测试的聚焦算法后续工作。

Tier C：500+ 张照片，压力/手工工作流验证。

- 当产品负责人希望对长复核会话、大组列表、导出行为或工作流工效更有把握时使用。
- 这是有用的发布证据，但不能替代仔细的 Tier B 算法复核。
- 除非另行安排并有意记录，否则不要为本文档任务尝试 2,000 张照片的真实浏览器-后端基准。

生成的合成图像不是真实世界验证。它们仍可用于可重复的自动化回归和性能检查，但不能满足本手工算法置信度门槛。

## 4. 推荐照片类别

在安全的前提下尽量包含这些类别：

- 连拍序列。
- 近重复旅行照片。
- 风景场景。
- 人像。
- 室内低光。
- 欠曝图像。
- 过曝图像。
- 有意模糊的图像。
- 构图重复、主体只有小变化。
- 混合方向图像。
- 无人脸图像。
- 若可得且非私人，多张人脸的图像。
- 视觉相似但无关、不应合并的场景。
- 裁切、缩放或元数据很少的图像。
- 技术上可接受、但创作偏好不明确的图像。

如果某个类别需要私人主体、敏感地点或许可不清，不要强行覆盖。

## 5. 手工复核工作流

1. 用 `git status --short` 确认工作树干净，或只包含有意的文档变更。
2. 为验证数据集创建一个本地 FramePilot 项目。
3. 只导入非私人的 JPEG、PNG 或 WebP 照片。
4. 在判断缩略图、预览、元数据或分数之前，等待导入任务到达终态。
5. 如果被测工作流不会自动开始处理，则运行处理。
6. 在判断组、推荐和解释之前，等待处理任务完成。
7. 记录总照片数和组数。
8. 复核各组，记录错误合并：不相关或有意义地分离的场景被放进同一组。
9. 复核附近未分组或单图照片，记录漏组：相似帧本应被分到一组。
10. 复核每个有意义的组，记录复核者选择与 FramePilot 代表帧或 Pick 推荐之间的排序不匹配。
11. 阅读推荐解释，记录解释不匹配：解释与可见原因或分数上下文不符。
12. 特别注意人脸和睁眼启发式用语。记录不匹配，但记住这些信号是实验性的。
13. 应用若干手工 Pick、Maybe、Reject、Unreviewed 和星级更新，确认用户覆盖仍然有效。
14. 至少为一组所选状态导出 CSV。
15. 检查 CSV 导出输出中的预期行、状态、组信息、推荐和敏感文件名。
16. 如果本次验证包含 ZIP 或文件夹导出，检查输出数量并确认原片未被修改。
17. 将导出问题与算法问题分开记录。
18. 避免提交生成产物、私人文件名、项目文件夹、导出、ZIP 文件、数据库或照片。
19. 在笔记模板中记录复核者结论和建议后续工作。

## 6. 需要记录的指标

每个数据集记录这些字段：

- 数据集名称或脱敏数据集 ID。
- 验证层级。
- 总照片数。
- 组数。
- 错误合并数。
- 漏组数。
- 排序不匹配数。
- 解释不匹配数。
- 导出问题。
- 复核者结论。
- 建议后续工作。

可选但有用的指标：

- 单图组数量。
- 多图组数量。
- 复核后标记为 Pick、Maybe、Reject 和 Unreviewed 的照片数量。
- 人脸信号不匹配数量。
- UI 工作流问题数量。
- 复核耗时。

## 7. 问题类别

错误合并（false merge）：

- FramePilot 把不相关照片、不同瞬间，或有意义地分离的构图放进同一组。

漏组（missed group）：

- 复核者期望一组时，FramePilot 把相似连拍或近重复照片留成分开的。

不良排序（bad ranking）：

- 组内已有明显更好的技术候选时，FramePilot 推荐了更弱的候选。

误导性解释（misleading explanation）：

- 解释强调了错误的可见问题、过度陈述置信度，或未提及推荐的主要原因。

人脸信号不匹配（face-signal mismatch）：

- 实验性人脸或睁眼信号看起来不正确影响了排序或解释。

曝光/对比度不匹配（exposure/contrast mismatch）：

- 曝光或对比度评分与可见图像质量反复冲突。

锐度/模糊不匹配（sharpness/blur mismatch）：

- 锐度或模糊评分与可见对焦或运动模糊反复冲突。

导出不匹配（export mismatch）：

- CSV、ZIP 或文件夹导出包含错误行、错误状态、缺失所选照片、损坏输出、不安全路径，或令人困惑的本地输出行为。

UI 工作流问题（UI workflow issue）：

- 复核者无法高效检查组、应用覆盖、导航照片、理解进度或确认导出结果。

## 8. 发布决策指引

建议的发布门槛：

- 无关键数据安全问题。
- 无原始文件修改。
- 无自动删除源照片。
- 无私人或生成产物被提交。
- 无严重导出损坏。
- Tier B 验证中无频繁错误合并。
- 无误导性声称：人脸或睁眼启发式是专业检测、身份识别、生物特征分析或可靠的人像判断。
- 当解释诚实、置信度保守且用户覆盖有效时，排序不匹配可以接受。
- 人脸和睁眼启发式不匹配仅在被记录为实验性限制、且对已验证工作流不构成发布阻断时可以接受。
- 阈值或代码变更在发布前需要聚焦测试。

建议结论：

- Pass：验证支持在接受已知限制的前提下打发布候选标签。
- Pass with notes：验证支持打标签，但后续问题应在发布后跟踪。
- Needs more validation：证据过小、过于合成、过于私人或过于含糊，无法决定。
- Blocked：必须在发布前修复数据安全问题、严重导出问题、频繁错误合并模式或误导性解释模式。
- Waived：发布负责人明确接受在没有本证据的情况下发布，并在发布说明中记录豁免。

不要要求 FramePilot 匹配每一个主观创作选择。v2.0 目标是保守、可解释的辅助加上人工覆盖，而不是全自动创作选择。

## 9. 何时调算法

不要根据单个轶事例子调整阈值。

只有在非私人验证证据或确定性真实夹具中观察到重复模式之后，才调整分组、排序、评分或解释行为。在更改阈值或逻辑之前：

- 确认期望行为足够清晰，可以编码进确定性测试。
- 为受影响的评分、分组、排序、解释、导出或状态更新行为添加或更新聚焦测试。
- 检查该变更不会增加错误合并、过度自信的 Pick、误导性人脸/睁眼用语或导出风险。
- 为 v2.0 保持实现本地优先且确定性。
- 当评分语义、权重、置信度标签或解释含义变化时，更新 `docs/scoring.zh.md`。
- 当变更影响发布风险时，更新发布评审或已知限制文档。

如果证据混杂，把问题记为验证笔记，保持阈值不变，并收集更多非私人例子。
