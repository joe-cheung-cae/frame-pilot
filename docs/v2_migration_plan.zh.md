# FramePilot v2 迁移计划

> 语言：[English](v2_migration_plan.md) | **中文**

FramePilot v2 应演进现有本地项目，而不要求用户重新导入照片库或危及原片。迁移必须是本地、确定性的，并可通过项目目录的常规文件备份回退。

## 迁移原则

- 永不修改或删除原始源照片文件。
- 把派生输出、元数据、缓存和导出留在项目控制的数据目录内。
- 优先做带默认值的加法 SQLite 变更，而不是破坏性重写。
- 让兼容迁移幂等，以便应用启动可以安全地多次运行它们。
- 只要所需源文件和生成产物仍存在，就保留 v1 项目数据。
- 保持不支持的 RAW、HEIC 和可选模型工作流关闭，除非它们在后续 v2.x 切片中被明确实现。

## 当前基线

当前 v2 基线使用本地 SQLite 元数据，以及 `.framepilot-data/projects/<project-id>/` 下的项目布局，包含：

- 复制的原片
- 缩略图
- 预览
- 缓存数据
- 导出

项目记录 `schema_version`、`source_mode` 和 `source_root_path`。v2 当前以 `copy` 模式创建项目；引用模式仍是计划中的未来存储模式。

启动时的数据库初始化使用由 `schema_meta.version` 行键控的版本化迁移运行器。全新数据库创建当前 SQLModel 表，并在每次进程启动时记录当前 schema 版本一次。较旧的本地数据库通过有序加法迁移升级；打开比当前构建更新的 schema 版本会以明确错误失败，而不是静默行为异常。

## SQLite Schema 演进

用加法迁移处理：

- 新的可空列
- 带安全默认值的新列
- 大项目复核、导出和任务查询的索引
- 未来 sidecar、模型或任务产物元数据的新表

避免这些迁移：

- 在未验证的情况下重写原始路径
- 丢弃用户复核决定
- 删除导出历史
- 假定生成的缩略图、预览或缓存文件仍然存在

当派生文件缺失时，处理应从复制的原片尝试本地重新生成。如果无法重新生成，该照片应进入可重试或失败的处理状态，而不是破坏项目迁移。

## 项目存储演进

Copy 模式是 v2.0 的安全基线。引用模式只应在这些行为经过测试后引入：

- 原始源路径仅作为引用存储
- FramePilot 永不写入被引用的原片
- 缺失的被引用原片产生明确、可重试的本地错误
- 导出仍写入项目控制的输出目录

未来 sidecar 导出应默认到项目导出目录，而不是原片旁边。在源原片旁写入 sidecar 应要求单独的用户选择工作流和额外的文件安全测试。

## API 兼容性

优先扩展现有响应，而不是破坏路由形状。当路由行为变化时：

- 更新 `docs/api.zh.md`
- 增加或更新 API 测试
- 在可行处保持现有 v1 工作流行为
- 返回明确的校验错误，而不是静默忽略不支持的输入

新状态值应在同一切片中反映到后端 schema、前端 TypeScript 类型、UI 状态和测试。

## 前端状态迁移

浏览器本地复核状态是按项目的。前端持久化应能容忍：

- 缺失的存储值
- 畸形的存储值
- 过期的过滤器、照片或组引用
- 后续版本新增的工作区标志

当持久化状态不可信时，UI 应回退到有效默认值，并保持项目可用。

## 验证清单

在提交与迁移相关的变更之前：

- 在适用时为幂等迁移行为增加测试
- 验证现有的项目创建、导入、处理、复核和导出测试仍然通过
- 运行 `npm run verify`
- 记录用户可见的行为变化
- 确认没有加入私人照片、生成数据集或大模型文件
