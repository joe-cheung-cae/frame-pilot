# S9.08 — Opt-in import concurrency (contract)

> Language: **English** | [中文](2026-09-04-s908.zh.md)

This page is the locked S9.08 contract for [#168](https://github.com/joe-cheung-cae/frame-pilot/issues/168). Living plan: [2026-09-04-remaining-stretch.md](2026-09-04-remaining-stretch.md) §5 S9.08.

**Hole (live tree):** `run_import_derivative_job` walks `photo_ids` in one sequential `for` loop and calls `process_registered_import_photo` on that job session (`apps/api/app/services/importing.py`). No `import_workers` setting, no `GET`/`PATCH /api/settings`, no `{data_dir}/app_settings.json`. `Settings` in `apps/api/app/core/config.py` is only `data_dir` / `project_root_allowlist` / `job_reclaim_on_startup`. `GET /api/meta` returns `version` / `service` / `data_dir` / `desktop_mode`. `SettingsPanel` is read-only data-directory plus localStorage export-status checkboxes. `python -m app.worker` holds exclusive `framepilot-worker.lock` and runs one claimed job at a time. `POST /process` already returns the existing blocking processing row for that project. SQLite WAL + `busy_timeout=5000` + `check_same_thread=False` are already on. `docs/v2_known_limitations.md` Desktop 2.1 still says there are **no concurrency knobs**. GitHub #168: default remains one import/processing worker; Settings may raise **import derivative** workers to 2–4 opt-in; one processing job per project; no Redis/Celery.

**Identity:** Opt-in **import derivative** thread count inside one import job. Not extra OS worker processes, not a second import job, not processing parallelism. Persist `import_workers` as an integer **1–4**, default **1**, in `{data_dir}/app_settings.json` (atomic tmp + replace, same family as `desktop_project_roots.json`). API-owned so the sidecar honors it. **Do not** use `localStorage`. **Do not** add Redis, Celery, Dramatiq, RQ, or `ProcessPoolExecutor`. **Do not** spawn extra `python -m app.worker` processes or drop the exclusive worker lock. **Do not** bump `CURRENT_SCHEMA_VERSION`. **Do not** put the knob on `GET /api/meta`. Snapshot the clamped value once at the start of `run_import_derivative_job` (BackgroundTasks, reclaim threads in `app.main`, and `python -m app.worker`); a mid-job PATCH must not resize the in-flight pool. Register/copy stays sequential (existing FD / chunk bounds). **Originals are never modified or deleted.**

**Settings API:** GET `/api/settings` → `200` `{ "import_workers": 1 }` (missing/corrupt file → 1). PATCH `{ "import_workers": 2 }` → `200` persisted. PATCH `{}` or omitted key → `200` current. PATCH `0` / `5` / `1.5` / `"2"` / `null` → `422`. Always available (web and desktop; not `FRAMEPILOT_DESKTOP` gated). Pydantic `int` with `ge=1`, `le=4`. File payload is `{"import_workers": <n>}`. Do not persist a cache knob in this slice.

**Import derivatives:** After `claim_job_atomic`: `import_workers==1` keeps the existing sequential per-photo loop, per-stage `progress_callback`, and cancel checks before/after each photo. `2–4` uses `concurrent.futures.ThreadPoolExecutor(max_workers=n)` over remaining photo ids. Each task opens its **own** `Session` (`get_engine()`). **Do not** share the coordinator session across threads. Peak concurrent `process_registered_import_photo` ≤ n (hence ≤ 4). Coordinator owns job-row writes behind a `threading.Lock`. Count `processed_items` / `failed_items` as tasks **complete**. Cancel stays cooperative: stop scheduling new photos when `cancellation_requested`; wait for in-flight photos; then existing `_cancel_import_job`. Do not `shutdown(wait=False)` / kill threads.

**Processing:** No pool. `run_processing_job` / `group_similar_photos` stay sequential. `POST /process` still returns the existing blocking row for that project. Do not add a processing-worker setting. One processing job per project remains the existing 409/reuse guard. One import job per project stays 409.

**UI:** `SettingsPanel` section **Import workers**, values **1 / 2 / 3 / 4**, default **1**. Load `api.getSettings`, save `api.patchSettings`. Helper: more workers can speed thumbnail and preview generation on large imports; grouping and ranking stay one job per project; originals stay unchanged; the value applies to the **next** import job. Not desktop-only. Do not persist this in `localStorage`.

**Docs (implementation commit):** replace “no concurrency knobs” in `docs/v2_known_limitations.md` (+ zh). Document GET/PATCH `/api/settings` in `docs/api.md` (+ zh). Short architecture note. User guide (+ zh) Settings sentence. README (+ zh) if needed. CHANGELOG Unreleased: new S9.08 subsection. Do **not** rewrite `docs/desktop_development_plan.md` §2.2 / §5.4 / §5.6 as shipped (S9.13). No `APP_VERSION` bump. Tick remaining-stretch §3 S9.08 `[x]` (en+zh) only in the implementation commit. Do not tick S9.09–S9.13.

**Files:** `apps/api/app/core/app_settings.py` (new); `apps/api/app/schemas/api.py`; `apps/api/app/api/routes.py`; `apps/api/app/services/importing.py`; `apps/api/tests/test_app_settings.py` (new); import-derivative tests; `apps/web/src/lib/api.ts`; `apps/web/src/components/SettingsPanel.tsx` (+ test); docs listed above + CHANGELOG Unreleased (+ zh); this plan (+ zh) §3 S9.08 tick.
