# S9.08 — 可选导入并发（合同）

> 语言：[English](2026-09-04-s908.md) | **中文**

本页是 [#168](https://github.com/joe-cheung-cae/frame-pilot/issues/168) 的锁定 S9.08 合同。活计划：[2026-09-04-remaining-stretch.zh.md](2026-09-04-remaining-stretch.zh.md) §5 S9.08。

**现场空洞：** `run_import_derivative_job` 用单层顺序 `for` 遍历 `photo_ids`，并在该作业 session 上调用 `process_registered_import_photo`（`apps/api/app/services/importing.py`）。没有 `import_workers` 设置，没有 `GET`/`PATCH /api/settings`，也没有 `{data_dir}/app_settings.json`。`Settings` 只有 `data_dir` / `project_root_allowlist` / `job_reclaim_on_startup`。`GET /api/meta` 只返回 `version` / `service` / `data_dir` / `desktop_mode`。`SettingsPanel` 是只读数据目录加上 localStorage 导出状态勾选。`python -m app.worker` 持有独占的 `framepilot-worker.lock`，一次只跑一个已 claim 的作业。`POST /process` 在该项目已有阻塞处理作业时返回现有行。SQLite WAL + `busy_timeout=5000` + `check_same_thread=False` 已经开启。`docs/v2_known_limitations.zh.md` Desktop 2.1 仍写**没有**并发旋钮。GitHub #168：默认仍是一个导入/处理 worker；设置可将**导入衍生** worker 升到 2–4（opt-in）；每个项目一个处理作业；不要 Redis/Celery。

**身份：** 单个导入作业内部的可选**导入衍生**线程数。不是额外的操作系统 worker 进程，不是第二个导入作业，也不是处理并行。把 `import_workers` 持久化为整数 **1–4**，默认 **1**，写入 `{data_dir}/app_settings.json`（原子 tmp + replace，与 `desktop_project_roots.json` 同类）。由 API 拥有，sidecar 才能遵守。**不要**用 `localStorage`。**不要**加 Redis、Celery、Dramatiq、RQ 或 `ProcessPoolExecutor`。**不要**再起 `python -m app.worker` 进程，也不要丢掉独占 worker 锁。**不要**升 `CURRENT_SCHEMA_VERSION`。**不要**把旋钮放进 `GET /api/meta`。在 `run_import_derivative_job` 开始时快照一次夹紧后的值（BackgroundTasks、`app.main` 的 reclaim 线程、以及 `python -m app.worker`）；作业中途 PATCH 不得改正在飞的池大小。登记/拷贝仍顺序。**永不修改或删除原片。**

**设置 API：** GET `/api/settings` → `200` `{ "import_workers": 1 }`（文件缺失/损坏 → 1）。PATCH `{ "import_workers": 2 }` → `200` 已持久化。PATCH `{}` 或省略该键 → `200` 当前值。PATCH `0` / `5` / `1.5` / `"2"` / `null` → `422`。始终可用（web 与桌面；不要用 `FRAMEPILOT_DESKTOP` 门控）。Pydantic `int`，`ge=1`，`le=4`。文件载荷为 `{"import_workers": <n>}`。本切片不要持久化 cache 旋钮。

**导入衍生：** `claim_job_atomic` 之后：`import_workers==1` 保持现有按照片顺序循环、分阶段 `progress_callback`，以及每张前后的取消检查。`2–4` 对剩余 photo id 用 `concurrent.futures.ThreadPoolExecutor(max_workers=n)`。每个任务打开**自己的** `Session`（`get_engine()`）。**不要**跨线程共享协调器 session。并发 `process_registered_import_photo` 峰值 ≤ n（因而 ≤ 4）。协调器在 `threading.Lock` 后拥有作业行写入。`processed_items` / `failed_items` 按任务**完成**计数。取消仍是协作式：见到 `cancellation_requested` 就停止调度新照片；等在飞照片结束；再走现有 `_cancel_import_job`。不要 `shutdown(wait=False)` / 杀线程。

**处理：** 不要池化。`run_processing_job` / `group_similar_photos` 仍顺序。`POST /process` 仍对该项目返回现有阻塞行。不要加处理 worker 设置。每个项目一个处理作业仍是现有的 409/复用守卫。每个项目一个导入作业仍 409。

**UI：** `SettingsPanel` 小节 **Import workers**，取值 **1 / 2 / 3 / 4**，默认 **1**。用 `api.getSettings` 读取、`api.patchSettings` 保存。说明：更多 worker 可加快大导入的缩略图/预览；分组和排序仍是每项目一个作业；原片不变；该值作用于**下一次**导入作业。不是仅桌面。不要写入 `localStorage`。
