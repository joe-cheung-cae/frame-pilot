# FramePilot v2 架构

> 语言：[English](v2_architecture.md) | **中文**

FramePilot v2 是一款本地 Web 应用，前端使用 Next.js，后端使用 FastAPI。浏览器与本地 API 通信；后端负责项目元数据、本地文件衍生件、处理、分组、排序和导出。

## 系统形态

```text
apps/web  ->  local HTTP API  ->  apps/api
                              ->  SQLite metadata
                              ->  local project directories
```

v2.0 架构中不包含云服务、用户账户、支付系统或远程照片处理依赖。

## 后端职责

FastAPI 后端负责：

- 项目创建与项目列表
- 导入校验与本地复制模式存储
- 缩略图与预览图生成
- 元数据提取与文件身份记录
- 处理任务与进度状态
- 确定性评分、分组、排序与解释
- 照片状态与星级更新
- 导出产物创建与下载安全
- SQLite 兼容性迁移与性能索引

当前路由集合记录在 [API](api.zh.md)。路由组织可以稍后拆分，但除非测试与文档在同一切片中一并更新，路由行为应保持向后兼容。

## 前端职责

Next.js 前端负责：

- 项目创建与工作流路由
- 导入、处理、筛选与导出界面
- 任务轮询、处理进度展示，以及分页的本地处理历史
- 键盘优先的复核状态
- 状态与星级的乐观更新
- 有界首页加载，以及对大量照片、分组、胶片条和对比视图的有界渲染
- 导出选择摘要，以及带“加载更多”控件的分页导出历史

可复用的复核与进度逻辑应尽可能放在 `apps/web/src/lib`，以便单元测试覆盖行为，而不必为每条细小状态规则都写浏览器组件测试。

## 存储布局

FramePilot 默认将本地项目数据存放在 `.framepilot-data/projects/<project-id>/` 下：

```text
project-root/
  originals/
  thumbnails/
  previews/
  cache/
    hashes/
    embeddings/
    jobs/
  exports/
    csv/
    zip/
    folders/
  logs/
```

v2.0 使用复制模式：导入的原图会被复制到项目目录中，之后保持不动。已记录 `source_mode`、`source_root_path` 和 `schema_version`，以便日后引入引用模式而不改变当前安全基线。

## 数据模型

核心表：

- `Project`
- `Photo`
- `PhotoGroup`
- `ProcessingJob`
- `ExportRecord`

照片记录来源身份、复制后的路径、文件元数据、感知哈希、质量分数、处理状态、复核状态、星级、分组 id，以及推荐解释。

处理任务记录任务类型、状态、当前步骤、总条目数、已处理条目数、失败条目数、进度百分比、错误消息、开始时间和完成时间。

导出记录存储模式、状态、所选状态、所选数量、输出路径和创建时间。

## 处理架构

处理使用本地 FastAPI 后台任务，配合持久化的 SQLite 任务记录：

1. 创建或复用一个处理任务。
2. 将任务 id 返回给前端。
3. 在排队或运行期间轮询任务端点。
4. 校验已生成的文件，并在可能时重新生成缺失的衍生件。
5. 根据当前照片构建分组输入。
6. 分组、排序、解释，并持久化结果。
7. 将照片状态标记为已完成、失败或跳过。

对未变更且已完整处理的项目再次运行时，会在不重建分组的情况下完成。过期的活动任务会被标记为失败，并在下一次处理请求时被替换。

## v2.0 Worker 决策

决策日期：2026-06-04。

FramePilot v2.0 将保留当前的本地进程内任务架构，而不是在发布前增加独立的 worker 进程。导入仍受上传限制，因为浏览器仍需将所选本地文件传输到本地 API；在该请求期间，导入任务会暴露本地进度和跳过文件计数。处理使用 FastAPI 后台任务与 SQLite 任务记录、过期任务恢复、可重试的照片状态，以及对未变更已完成项目的幂等重跑。

这是一项已接受的 v2.0 限制，而不是永久架构目标。该决策避免在用更多真实照片证据验证确定性本地工作流之前，增加打包、生命周期和迁移复杂度。当 1,000 到 2,000 张照片的真实浏览器-后端运行表现出不可接受的阻塞、内存压力或频繁的中断恢复需求时，应重新考虑独立的本地 worker。

## 算法边界

分组与排序默认是确定性的：

- 分组使用候选窗口、元数据兼容性、感知哈希距离、embedding 回退、并查集，以及时间跨度拆分
- 排序使用可解释的质量信号，并做小幅上下文感知的权重调整
- 分组摘要会持久化置信度与推荐计数

可选 AI 模型被延后；一旦引入，必须保持本地且可选。

## 导出架构

导出将衍生产物写入项目导出目录：

- CSV 写入选择清单
- ZIP 打包所选文件
- 文件夹模式将所选文件复制到本地导出文件夹

CSV 和 ZIP 在成功完成后提供浏览器下载端点。文件夹导出暴露本地路径。失败的导出会保留历史记录，并在可能时删除不完整产物。

未来的 sidecar 导出应默认写入由项目控制的导出目录，并且在没有用户明确选择的工作流变更时，不得写到原始源文件旁边。

## 迁移与索引

SQLite 启动时会对加性列和索引应用幂等兼容性迁移。现有迁移覆盖项目存储元数据、照片文件身份字段、处理状态、导出状态元数据、分组分数摘要，以及大型项目查询索引。

后续 schema 变更应遵循 [迁移计划](v2_migration_plan.zh.md) 中的规则。

## 桌面壳

可安装桌面应用是 Tauri 2 窗口加本机回环 Python sidecar。它通过 HTTP 复用共享筛选 UI，且永不修改原图。见 [桌面用户指南](desktop_user_guide.zh.md)、[桌面测试矩阵](desktop_testing.zh.md) 与 [桌面打包计划](plans/2026-08-18-desktop-packaging.zh.md)。
